Post Installation

Windows

Microsoft Visual C++ runtime for FlashPro debugging

The fpServer process that owns the connection to a FlashPro programmer is a 32-bit component, so it needs the 32-bit Microsoft Visual C++ runtime present on the machine.

The Windows installer is configured to install this runtime for you. After the files are copied, it runs the redistributable included with SoftConsole v2022.2-RISC-V quietly and without restarting the machine:

<SoftConsole-install-dir>/extras/vcredist/vc_redist.x86-14.51.36247.exe

This step is configured to continue without reporting an error if the redistributable does not complete, so installation is not interrupted. That means a failure here is not surfaced at install time.

If a debug session fails to start and the fpServer console reports a missing DLL, the runtime is most likely not present. Run the redistributable from the directory above and try again. Administrator rights may be required.

PolarFire SoC boot mode programming

When using PolarFire SoC boot mode programming tool from within SoftConsole then Program and debug, or Libero has to be installed. This is a separate installation from SoftConsole, and the release installed must support the target device and the programming operation. For the RT PolarFire SoC devices RTPFS460ZT/ZTS/ZTL/ZTLS and RTPFS160ZT/TS/TL/TLS, programming support was added in v2025.1:

https://www.microsemi.com/product-directory/dev-tools/4970-programming

https://www.microchip.com/en-us/products/fpgas-and-plds/fpga-and-soc-design-tools/fpga/libero-software-later-versions

Renode dependencies

The Renode emulation platform is not a crucial sub-module of SoftConsole and users who are intending to connect to hardware targets only do not need satisfy the Renode’s dependencies.

The Renode build bundled with SoftConsole v2022.2-RISC-V carries its own .NET runtime and is started from a native executable, so the separate .NET Framework step that earlier releases described is no longer needed.

Note

Earlier releases asked for .NET Framework 4.8 to be enabled through the Windows features dialog. That step does not apply to this release.

Windows firewall

On Windows if there is a firewall in use then the first time that a debug session is run the firewall may prompt that it is blocking OpenOCD, fpServer.exe and/or renode.exe. Allow the firewall to unblock these and save this as the default setting if necessary.

Linux

Many of the commands below require root privileges using su, sudo or by logging in as root.

  1. Many platforms have gcc and make packages installed by default, but it is advisable to make sure that these are installed.

    Note

    Renode is using gcc for compiling just in time models. While make is used by Eclipse CDT to compile projects.

    sudo apt-get install build-essential
sudo apt-get install libwebkit2gtk-4.0-37 # To enable SoftConsole embedded web-browser

    sudo yum groupinstall 'Development Tools'

  2. It is recommended that the Linux platform used to run SoftConsole has all available updates installed.

    Note

    It may be possible to install and run SoftConsole on other Linux distributions or versions once the required packages are installed. However, some earlier distributions (for example, CentOS/RHEL 5.x and 6.x) may not work and are not recommended or supported.

Program and Debug PolarFire SoC

If you want to use mpfs programmer you need to install Program and debug, or Libero. This is a separate installation from SoftConsole, and the release installed must support the target device and the programming operation. For the RT PolarFire SoC devices RTPFS460ZT/ZTS/ZTL/ZTLS and RTPFS160ZT/TS/TL/TLS, programming support was added in v2025.1:

https://www.microsemi.com/product-directory/dev-tools/4970-programming

https://www.microchip.com/en-us/products/fpgas-and-plds/fpga-and-soc-design-tools/fpga/libero-software-later-versions

Renode dependencies

The Renode build bundled with SoftConsole v2022.2-RISC-V is the portable .NET build and carries its own .NET runtime inside the installation’s renode folder. No Mono framework and no separate .NET installation are required.

Note

Earlier SoftConsole releases bundled a Renode build that ran on the Mono framework, so their setup instructions asked for Mono to be installed from the mono-project repository. Those instructions no longer apply to SoftConsole v2022.2-RISC-V.

The bundled runtime is self-contained, but like any native application Renode still links against libraries provided by the host. These are ordinary system libraries rather than a framework to install, and the set required depends on the distribution and on which Renode features are used, so no package list is given here. If Renode does not start, run it directly to see the loader’s own error, which names the missing library:

"<install-dir>/renode/renode" --version

A successful run prints the Renode version and the bundled runtime, for example Renode v1.16.1.4403 and runtime: .NET 8.0.12. Install whichever library the error names using the host’s package manager, and refer to the Renode documentation bundled with the installation for emulation-specific requirements.

Additional dependencies

The bundled Renode carries its own .NET runtime, so no framework has to be installed for it to run. The packages below are needed only for additional activities such as Robot testing or building Renode from its sources, and several are likely already present with a generic GUI desktop environment. Most users can skip this step. The list is inherited from the upstream Renode build instructions and includes items, such as the Mono GTK bindings, that the bundled build itself does not use.

On Ubuntu they can be installed with the following commands:

sudo apt-get install git automake autoconf libtool g++ realpath gcc libc6-dev
sudo apt-get install policykit-1 libgtk2.0-0 screen uml-utilities gtk-sharp2 rpm libarchive-tools
sudo apt-get install python3 python3-pip python3-setuptools python3-dev ruby ruby-dev 
sudo gem install fpm

Writing models for Renode

Users, wishing to write Renode models can use Mono Develop IDE as their C# editor. Renode is made as a Mono Develop project, therefore it should be able to open Renode’s sources without any extra manual steps.

Hardware targets (FlashPro)

Note

When accessing FlashPro devices then native Windows/Linux host machines are recommended as there might be issues with Virtual Machines accessing the FlashPro.

Check that FlashPro can be used without root privileges

Connect a FlashPro5/6 JTAG programmer to a native Linux host machine (this might not work on a VM) and check that it is visible to the operating system:

lsusb
Bus 001 Device 004: ID 1514:2008 Actel
Bus 001 Device 004: ID 1514:2009 Actel
Bus 002 Device 002: ID 1514:200b Actel

If the FlashPro5 (VID=1514 PID=2008) or FlashPro6 (VID=1514 PID=2009) or embedded FlashPro6 Rev B (VID=1514 PID=200b) does not appear then double check that the previous steps were carried out correctly.

Warning

If you will see VID=1514 PID=200a then that is embedded FlashPro6 Rev A and to use it with SoftConsole or Libero, it needs to be upgraded to Rev B.

  • To the JTAG end of the FlashPro connect a suitable board containing a Cortex-M1, SmartFusion or SmartFusion2 Cortex-M3, or RISC-V CPU based SoC design.

  • To the JTAG end of the FlashPro connect a suitable board containing a RISC-V CPU based SoC design.

    • Make sure you are connecting to the right JTAG connector (in case of Icicle board it’s J23 and not J10, the J10 is used only to reprogram the embedded JTAG)

  • Power the board on.

  • Make sure that the board is configured for FlashPro JTAG debugging of the target CPU (depending on the board and CPU/SoC in use some board switches/jumpers configuration may be required).

  • Make sure that it has correct and matching Libero design (if you are going to connect to Mi-V RV-32 then you need working Mi-V design on the device)

  • Run OpenOCD from the command line to ensure that the debug connection can be established to the target CPU/SoC:

First go to the correct directory (replace <SoftConsole-install-dir> with your installation path):

cd <SoftConsole-install-dir>/openocd/bin

And then execute the following:

./openocd -c "set DEVICE MPFS" -f board/microsemi-riscv.cfg

./openocd -f board/microsemi-riscv.cfg

./openocd -f board/microsemi-cortex-m1.cfg

./openocd -c "set DEVICE M2S090" -f board/microsemi-cortex-m3.cfg

Note

A M2S090 target is needed in the example above.

For example: When using Trenz SMF2000 board, it needs to be changed to M2S010.

The command set DEVICE M2S090 needs to be changed to match the target.

Enabling non-root user to access FlashPro

By default, USB devices are only accessible to users with root privileges. To debug using SoftConsole and FlashPro5/6 as a non-root user some additional steps must be taken.

  • Copy the OpenOCD udev rules file and tell the udev subsystem to load it. This rules file describes all USB JTAG devices supported by OpenOCD to the system and makes them accessible by non-root users (replace <SoftConsole-install-dir> with your installation path):

    cd <SoftConsole-install-dir>/openocd/openocd/contrib
sudo cp 60-openocd.rules /etc/udev/rules.d
sudo udevadm trigger # Or reboot the PC for the changes to take effect

    If /etc/udev/rules.d/60-openocd.rules already exists then make sure to overwrite it with the new version in this release as it contains additional rules that are not included in the earlier version.

    Note

    The location of this file changed in SoftConsole v2022.2-RISC-V. Earlier releases kept it in openocd/share/openocd/contrib. If you are following instructions from an older release and that directory does not exist, use the path above.

    Note

    If SoftConsole is installed alongside other tools which affect the udev rules (for example Libero, Program and Debug), then make sure their rules/scripts do not override the rules from the 60-openocd.rules file.

    In some cases it may be necessary to reboot for the changes to take effect. Some distributions do not create the plugdev group and/or may not add users to it automatically. In that case the plugdev group must be created manually and the user added to the plugdev group.

    Note

    In SoftConsole v2022.2-RISC-V the FlashPro rules grant access with MODE="666" as well as naming the plugdev group, so membership of plugdev is normally not required. The group steps below are still worth following if your site policy restricts device permissions, or if another tool installs stricter rules for the same devices.

    sudo groupadd plugdev
sudo usermod -a -G plugdev <username>

    Log out and then log in (or reboot the PC) for the usermod changes to be applied.

  • Provision the FlashPro CYUSB configuration. fpServer reads /etc/cyusb.conf when it initialises; if that file is missing, FlashPro programmer enumeration fails and the Debugger tab reports “Enumeration failed”. An administrator runs (replace <SoftConsole-install-dir> with your installation path):

    sudo "<SoftConsole-install-dir>/fpServer/fpserver-setup.sh" --install

    This creates /etc/cyusb.conf and /etc/udev/rules.d/88-cyusb.rules if they are not already present, by running the bundled, unmodified Microchip fp6_env_install script, then reloads the udev rules for you. Unplug and replug the FlashPro programmer so the new rule applies to it. If the command reports that reloading udev failed, reload it manually or reboot.

    If either file already exists it is validated first. A supported existing configuration is preserved: the FlashPro6 entry is merged into it, other device entries are kept, and a timestamped backup is taken before the file is modified. If a file is present but its contents are not in the expected form, the command reports what it found and what to add instead of changing it. If setup reports an error, read it and resolve its cause before continuing, and follow any recovery instructions it prints. Recovery from a failed installation is best effort, using the backups taken of files that already existed.

    To validate the configuration without changing anything:

    "<SoftConsole-install-dir>/fpServer/fpserver-setup.sh" --check

    --check inspects the configuration files only. It does not test hardware connectivity and does not confirm that a programmer is attached. To check that a programmer is enumerated:

    "<SoftConsole-install-dir>/fpServer/run_fpserver.sh" --list

    Note

    These files are shared with other Microchip tools. If Libero or Program and Debug Tools is installed they may already exist, and uninstalling SoftConsole does not remove them. See fpServer/FLASHPRO-SETUP-README.txt in the installation for the configuration details and for how to undo the change.

Note

If you previously used SoftConsole v4.x or 5.0 and installed the 99-openocd.rules file into /etc/udev/rules.d then you can delete that file as it is now redundant and superseded by 60-openocd.rules. Then run again:

sudo udevadm trigger # Or reboot the PC for the changes to take effect

For all other common issues read the troubleshooting section. Or at least search for the error messages.
